# 发布清单与历史归档

## 当前发布流程

1. 确定应用版本，同步项目中相应的版本来源并运行完整验证。科学模型与内部格式版本按实际行为独立管理。
2. 提交最终修改，确认工作区干净。先创建一个仓库外的交付目录。
3. 运行下面的命令，输出文件必须不存在，父目录必须已存在。

```bash
npm run release:manifest -- "<仓库外的交付目录>/release-manifest.json"
```

生成器只枚举 Git 跟踪的源码文件，包含文档与历史归档，排除忽略的依赖、缓存、备份和本地产物。它对应源码交付；如另做精简站点包，需对该包单独生成校验清单。

清单记录应用版本、最终提交、文件范围与每个文件的校验值，文件总数从列表计算。输出位于仓库外，不能包含自身，也不会覆盖已有清单。清单不代替测试证据，不写未经执行的测试通过数。

校验基于本地文件实际字节，Windows 与其他系统的换行转换可能产生不同摘要；应从生成清单时的同一目录打包，不能用该清单校验另一种换行形式的 GitHub 自动源码包。修改文件后需重新验证、提交并生成新清单。

## 历史清单

[`v1.0.0/RELEASE_MANIFEST.txt`](./v1.0.0/RELEASE_MANIFEST.txt) 为原始历史记录，保持其日期、内容与原有统计。里面的相对路径指历史交付根目录，不指本归档目录；它不描述当前工作区，也不参与当前构建或测试门禁。

该旧清单包含自身哈希，不能作为自校验文件使用；保留它仅为追溯原始发布记录，新清单由上述命令独立生成。
