# 发布与回滚

## 静态部署

项目不需要编译或安装依赖。将项目根目录原样发布到支持静态文件和自定义响应头的平台即可。

Cloudflare Pages 建议配置：

- Build command：留空；若必填，使用 `echo "static site"`。
- Build output directory：`/`。
- Root directory：包含 `index.html`、`src/`、`assets/`、`sw.js` 和 `_headers` 的项目目录。

## 发布后验证

- 确认 `index.html`、`src/app.js`、`src/simulation.worker.js` 和 `sw.js` 返回 200。
- 在 DevTools 中确认 Worker 成功启动，控制台无模块加载错误。
- 确认响应头中的 CSP 不阻止同源 Worker 和模块。
- 清理旧页面标签并刷新，确认缓存名升级为 `tme-aquarium-v1.1.0`。
- 运行六场景、五种干预、证据页和 v1/v2 存档 smoke test。
- 检查窄屏布局和 `prefers-reduced-motion`。

## 缓存升级

v1.1 的 Service Worker 激活时会删除其他名称的旧缓存。若发布后仍出现旧资源：

1. 确认线上 `sw.js` 的 `CACHE` 为 `tme-aquarium-v1.1.0`。
2. 确认 `sw.js` 使用 `Cache-Control: no-cache`。
3. 在浏览器 Application 面板注销旧 Service Worker，并重新加载一次。
4. 不要给 `index.html` 设置长期 immutable 缓存。

## 回滚到 v1.0

1. 保留当前 v1.1 包和 SHA-256 作为审计记录。
2. 用经过校验的 `TME_Aquarium_v1.0.0.zip` 内容覆盖部署目录。
3. 确认 v1.0 的 `sw.js` 已上线，并在客户端注销/更新 v1.1 Service Worker。
4. 在干净浏览器配置中重新执行 v1.0 smoke test。

## 数据兼容说明

- v1.1 可以迁移 v1 存档。
- v1.0 不理解 v2 存档；回滚前应提醒用户导出的 v2 JSON 不能直接导入 v1.0。
- 回滚不会自动删除浏览器本地存档。必要时由用户在应用或浏览器站点数据设置中清理。
